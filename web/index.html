The mechanism, with the numbers

Four doors. Every one raises backing per token.

A bonding curve on Meteora prices the token in USDC. The vault is a wallet anyone can read. Nothing leaves it except through a burn or a payment, at a printed price — and the fee from every trade buys the next item.

The itemsRead from the vault wallet on Solana with the DAS API, cached for seconds, age shown. Not a list we keep. Grade, certificate and physical vault come from the asset's own metadata. Vault wallet:
IndexThe Insured Value attribute written on chain by the custodian (Collector Crypt). An index they assign — not a market price, not a number of ours.
The 0.89×Cards sell for less than the index. 0.89× is the measured median across our own sales; backing is shown after that haircut, with its sample and date.
Market capPrice from the bonding curve × supply from the mint, both on chain, read on the server with the same decoder the open-source reader uses.
What we never doAdd liquidity to backing. Money that went up the curve is the pool's at migration, not the vault's. Two pockets, two numbers, never one total.
Who signsOnly the vault wallet, only to deliver through the two exit doors, only after a payment or a burn was read from the chain. The code that signs is public; the key is not.

Operator-run until the program ships.

A vault's whole value is its custody. Until the four doors are enforced by an on-chain program (escrow, rule-bound minting and release), a stranger's vault would rest on that stranger's word — and we will not put our name on that. Today Onix operates every vault; yours launches with us holding the keys under the published rules, and moves to the program when it exists.

Vaults›Integrate

For gachas, games and shops · public API

Sell what a vault holds. Three calls.

You never assemble a transaction by hand and the vault never touches your player's money. The price is the same for Onix's own gacha and for you, and it is printed on every item.

1
List

GET /v1/vaults/{vault}/items — what is inside, with the exit price and whether it is reserved.

2
Reserve

POST …/reservations only after your player paid you. You get back a payment transaction the vault built: sign it, send it.

3
Settle

POST …/reservations/{id}/settle with the signature. The vault reads the payment from the chain and delivers to your winner.

// examples/integrator/vaultClient.js — the client Onix.Cards' gacha runs in production
const vault = createVaultClient({ baseUrl: 'https://vault.onix.finance', vault: '4yTsiQXPPhbmXHgZSgp7NwUNVfjbjWLkdUN5YhQmyqRt' });

const items = await vault.items();                              // 1 · exitPriceUsd on every item
const r = await vault.reserve({ mint, integrator, winner, idempotencyKey: pullId });
const sig = await signAndSend(r.paymentTransaction);           // 2 · built by the vault, signed by you
const done = await vault.settle(r.reservationId, sig);        // 3 · 409 = not finalized yet, retry
console.log(done.deliverySignature);                            // the card is in your winner's wallet
SandboxThe same server against devnet with a test vault: npm run rehearse:vault in the public repo. Rehearsed 1 October: reserve → pay → settle → delivered, verified on the raw transactions.
LimitsReservations expire in minutes. Let three expire without settling and the vault stops taking yours. x-api-key is optional: it identifies you, it unlocks nothing.
Contractserver/openapi.json is the source; the docs follow it. Webhooks are roadmap — today you poll the reservation.
